# 标签值实体 v2：实施与迁移

日期：2026-11-02。公共契约为 `resources/tagging/`，包格式版本 2，内置包版本 2.0.0。本文取代旧设计中“具体选项也是标签声明”的模型。

## 对象与身份

| 对象 | 保存内容 | 可否接受业务标注 |
| --- | --- | --- |
| 标签声明 `definition` | 值约束、录入与展示、适用主体、查询、自动化 | 否 |
| 配置分组 `groups` | 多语言名称与描述 | 否 |
| 值集合 `vocabularies` | 多语言资料、启用状态、内置种子值 | 否 |
| 值实体 `term` | 稳定 ID、多语言名称/描述、别名、集合成员、独立修订 | 是 |
| 影片 `film` | 媒体身份与事实 | 是 |

“演员”是一个引用人物集合的字段，“某位演员”才是可标注年龄、性别、其他标签的实体。字段声明自身无需业务标注这个抽象；声明治理信息仍是配置元数据。改名、翻译、同名不同值不改变实体 ID。

引用编码是 `{ "term": "stable-id" }`；多值是这些对象的数组。固定枚举也具有实体身份，`encoding: "literal"` 可继续存储原有稳定标量，例如可见状态值；该标量同样解析到实体。`literal` 创建后不可修改，标签显示名不参与匹配身份。

`subjectVocabularies` 限制字段适用哪些值集合。普通标注只允许 `film` 和 `term`；实体只允许整体 scope，影片支持整体、时间点、区间。字段、实体、标注分别维护配置世代、实体修订、标注修订。

## 新版内置登记

安装包登记 27 个字段，全部带中英文名称和描述，系统层与用户层仍按 key 覆盖：

| 类别 | 字段 |
| --- | --- |
| 个人 | 评价、收藏、未看过 |
| 影片资料 | 标题、番号、简介、海报、显示状态、主演、厂牌、标签 |
| 媒体事实与状态 | 文件路径、文件大小、添加时间、修改时间、时长、画面宽度、画面高度、帧率、视频编码、音频编码、播放位置、资料来源、所属影片库 |
| 人物值属性 | 性别、年龄、出生日期 |

人物、厂牌、主题为可新增值集合；显示状态与性别为固定种子值集合。原“资料、个人、人物、厂牌、主题、媒体属性”成为 6 个配置分组，不再产生没有业务意义的布尔输入框。

人物属性由 `targets: ["term"]` 和人物集合限制声明；“标签”允许影片与实体主体，并放入 `term.details.fields` 区域。年龄为手动数字属性；出生日期为独立日期字符串，当前不自动推算年龄。这些规则全部位于内置资源，产品代码不识别演员、性别、年龄等业务 key。

## 引用图与查询

实体到实体的所有有效引用组成一张有向无环图，跨字段检查；标量只是节点属性。声明 `parents` 是另一张配置组织图。新增、覆盖、批量、导入、启用、配置发布都验证事务最终图。自环、跨字段环和批量内部环失败时整笔事务回滚。

`related` 查询对同一个关联实体执行内部谓词：

```json
{
  "op": "related",
  "tag": "core.cast",
  "where": {
    "op": "and",
    "args": [
      { "op": "gte", "tag": "core.person.age", "value": 25 },
      { "op": "lte", "tag": "core.person.age", "value": 35 }
    ]
  }
}
```

字段是否可查询仍受声明限制，嵌套深度最多 24，每个布尔节点最多 100 个条件。主体停用、集合移除或引用失效后，正常读取只得到有效交集；原始标注和审计保留。

## 界面与 Agent

- 标签管理分为“标签声明”和“标签值”。前者提供配置树、属性表及 Monaco，能新建字段、集合、配置分组；后者选择集合中的具体值，编辑值资料及属性。
- 实体属性由 `term.details` 布局和字段 placements 动态生成，支持 stack、grid、section、field-set；默认自动保存，提供撤销、重做。缺失数字显示空值，不暗示为 0。
- 值详情展示直接入边、出边及对应字段，点击邻接节点继续查看。当前图是可导航的一跳邻接视图，不是全库自由布局画布；单次返回至多 500 条链接，影片引用数是此返回范围内的计数。
- `terms.query/get/put` 作为公共 RPC 和 Agent 工具登记；新增选项只创建实体，不发布字段配置世代。读发现链允许查具体值和现有标注，写操作仍由原有审阅机制控制。
- `annotations.bulk.preview` 接受 `subjectKind: "film" | "term"`，冻结主体 ID、主体修订及标注修订。执行继续使用可暂停、停止、恢复的持久任务；并发变化记冲突，不覆盖。关联查询与实体批量目前通过查询协议/Agent 使用，未增加专用可视化关联筛选器或值合并向导。
- `KNOWLEDGE.md`、JSON Schema、能力描述及工具目录随 Core 同时打包到 Web/MAUI，通过 `knowledge.read`、`schema.get` 读取；旧 v1 资源仅为迁移与导入编解码器。

## 数据迁移

首次发现 v1 时，在数据库事务前用 SQLite 在线备份生成数据目录下的 `backups/before-value-entities-v2.db`；已有备份不会覆盖。随后一次事务完成：

1. 依据旧 `options.from.descendantsOf` 的真实集合成员关系识别选项声明，保留旧 key 作为 term ID，包含停用值；不以名称或布尔组件推断身份。
2. 共享选项声明转成实体，组根转成配置分组；字段的选项来源改为值集合。内联枚举生成带命名空间的固定实体，并保留原标量编码。
3. 原值之间的父子边写入兼容引用字段；图中的环整体隔离到诊断，原始历史不删除。旧选项曾作为布尔字段使用的记录保留为失效标注，不继续把值伪装成字段。
4. 影片引用 `{tag: old-id}` 转成 `{term: old-id}`。主体确认为选项的旧标注转到对应 term；写在字段声明上的标注转为只归档的 `legacy-definition`，禁止正常 API 新写，不猜测具体对象。
5. 旧 head 变化时新增修订，原 history 字节不改；原有效配置和迁移报告归档。候选数据、已存查询、工作区引用一并转换。
6. 字段草稿转换为 v2；组草稿转为 groups 配置，选项草稿转为值资料草稿并保留原 JSON。内联选项修改拆成集合草稿。未完成 JSON 原样保留；仅迁移引起的世代/修订变化可重定位草稿，真正并发修改仍冲突。
7. 重新编译内置加用户配置，验证有效投影，再提交。失败回滚，重复启动不重复执行。旧后台任务和预览不丢弃，使用旧世代的写入会报告冲突，需重新预览。

工作区带 `tagModelVersion: 2`；旧客户端在升级期间晚到的工作区保存也通过同一转换器处理。保留用户值、未发布配置和系统配置分开更新。

恢复时先停止对应宿主，保留升级后的完整数据目录，再将该在线备份恢复到独立目录并使用旧版本宿主打开。不要把旧 `catalog.db` 与新版遗留的 WAL/SHM 混用，也不要在正在运行的进程下替换数据库。此次升级不修改影片文件。

## 交换与兼容

定义包保存字段、配置、集合及固定种子实体；标注包保存实体目录和标注，合并包包含两者。单独导入标注如缺少配套声明/集合，数据可归档但不会越过有效性校验展示。导入冻结现有 term 和 annotation 修订，提交前再次检查；原文件保留于导入档案。

v1 定义文件原本包含选项身份及父子边，因此导入时内部转换为“定义加值目录及关系”，不会因只导入定义而丢掉旧选项。归档导出保留旧主体及无效数据的来源，正常业务读不回退到这些过期记录。

## 验证

自动测试覆盖值身份、同名独立、改名、主体限制、集合成员、有效交集、跨字段 DAG、批量 DAG、相同实体上的关联条件、值修订冻结、导入回滚、v1 单独定义导入、禁用固定值覆盖、迁移幂等、原始历史与草稿保留，以及 Agent 读发现到受审阅批量预览的工具链。

浏览器在独立资料库副本验证具体值属性自动保存、不同值不串写及直接关系图。实际运行数据的迁移计数、构建及平台验证范围记入 `VALIDATION.md`。Windows MAUI 进行构建验证；Android/iOS/macOS 本轮没有实机验收。Vite 仍有既存 Monaco 懒加载包体积提示。
