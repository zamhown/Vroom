# 客户端语言包

## 梳理结果

原有界面文案混在 JSX、`words` 表和中英二选一函数里；`startsWith('zh')` 把所有非中文语言都视为英文。启动固定中文，候选语言列表写死，通用控件、导航和编辑器使用不同机制。后台任务持久化中文，工具说明在宿主侧提前选定翻译。

现统一使用独立界面语言包；标签声明继续使用公共 `LocalizedText` 合同。未重写已有标签、标注、媒体和任务记录。新任务保存消息 ID 和参数，客户端显示时格式化；文件名、第三方日志和已有历史数据仍作为数据保留。

## 资源与运行时

- 使用 FormatJS `intl-messageformat` 和 ICU MessageFormat，支持复数、选择、数字、日期及具名参数。代码只引用稳定消息 ID；修改措辞不改 ID，不以原文充当键，不维护中英元组。
- BCP 47 标识规范化后，用 FormatJS `intl-localematcher` 匹配区域。仅在同语言、同文字系统内匹配，不把无关语言当作英文。
- `resources/localization/manifest.json` 是界面回退语言的唯一来源，第一期为 `zh-CN`；`packs/` 提供完整的 `zh-CN`、`en` 包。包包含版本、语言标识、本地名称、方向和消息字典。公共结构见 `language-pack.schema.json`。
- 语言包仅含数据，不含脚本、HTML 或网络入口。消息按普通文本渲染。新增消息同时补齐两个内置包，参数保持一致；计数用 ICU 复数，不拼接半句话。
- Spectrum/React Aria 管理控件内部文案和可访问行为，不再在构建时裁剪成固定两种语言。JSON 编辑器和媒体引擎的第三方原始诊断不被自定义文案替换。

## 启动、安装与切换

先载入内置和用户包，再读取 `vroom.locale` 客户端偏好。已有偏好时沿用；没有偏好时按系统语言顺序匹配。Windows 读取 `GlobalizationPreferences.Languages`，Mac Catalyst 读取系统首选语言；浏览器使用 `navigator.languages`，不使用服务端语言。无匹配则回退清单默认语言。选择保存后不再被系统语言覆盖；所选包缺失时回退并保存新的有效选择。

设置 → 语言支持切换、安装 JSON 包、卸载用户包。用户包存于应用数据数据库的 `language.pack.<locale>` 设置项；内置包随两个宿主发行，不能被用户包覆盖。允许第三方包缺项，逐条回退到默认包；内置包必须完整。损坏的已保存包在启动时隔离，设置页显示未载入状态并允许移除，不妨碍打开资料库。

宿主检查版本、标识、内置层保护、JSON 合同和消息 ID；同一个 FormatJS 校验器在客户端安装和载入时检查 ICU 语法及参数。未通过校验的包不参与渲染。公共 JSON Schema 随两个宿主打包，并通过 `language.schema` 读取。

切换语言更新 Spectrum Provider、文档 `lang` / `dir`、界面消息和静态工作区标题。不能把语言作为组件 key，不能重建工作区或挂载新视频；草稿和播放实例保留。

## 与标签声明并行

`package.i18n.defaultLocale` 是标签文案的全局录入及内容回退语言，独立于界面语言偏好。它通过正常配置预览、发布和代际校验修改。实例弹框没有“设为默认”；主表单直接编辑这个全局语言，缺少翻译时为空，不以回退文案伪装成已填写。

候选语言 = 有效声明中所有 `LocalizedText` 的语言键、共享消息 `i18n.messages.*` 的语言键 和默认语言声明的语言 ∪ 已安装有效语言包。当前草稿已有语言也保留。标识规范化后去重，`en` 和 `en-US` 仍是不同翻译键；不从任意业务数据的字符串键猜语言。卸载包不删除翻译，声明包含语言也不自动安装界面包。

宿主错误携带 ID 与 `errorArgs`；任务的 `Name`、`Detail`、`Error` 维持字符串合同，各带可选参数字典，显示时翻译。工具目录保留原始多语言说明。公共标签、布局及导出资源继续使用原有多语言合同，不复制进界面包成为第二份业务定义。

## 验证要求

检查包完整性、ICU 语法和参数、陌生语言安装、区域及文字系统匹配、首启与后续启动、消息回退、损坏包隔离、语言并集、卸载后翻译保留。检查源代码硬编码文案、语言分支与缺失 ID。后台检查包独立持久化和内置层保护。媒体测试使用状态与遥测，不能用某句翻译判断执行进度。

参考：[FormatJS ICU MessageFormat](https://formatjs.github.io/docs/intl-messageformat/)、[FormatJS LocaleMatcher](https://formatjs.github.io/docs/polyfills/intl-localematcher/)。
