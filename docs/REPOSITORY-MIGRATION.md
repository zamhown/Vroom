按后续请求将运行时准备接入 `npm run setup`，并重新完成 Windows 编译测试。默认入口安装 npm 依赖、还原 .NET 工具和 NuGet 包、检查桌面工作负载，并下载/校验 FFmpeg、ffprobe、HandBrakeCLI、mpv 与 Qwen。提供 `--web`、`--skip-model`、`--skip-runtime` 和独立 `setup:runtime` 入口。Windows CI 安装媒体工具并使用 `--require-media`，避免缺失运行时导致实际编解码测试被跳过。

新增两项文件锁回归测试，覆盖短暂锁释放、持续锁报错及已有输出保留。下载器回归覆盖镜像失败回退、有效缓存复用，以及校验失败不替换已安装文件。HandBrake 测试支持显式工具路径；完整检查会自动发现仓库自己的运行时。

## 普通 Windows 终端兼容修复（2026-11-14）

用户在普通终端遇到 `spawnSync pwsh ENOENT`。此前验证环境额外提供 PowerShell 7，未覆盖没有该命令的终端。现在 Node 入口共用 PowerShell 定位逻辑，依次查找 PATH、标准 PowerShell 7 安装目录和系统自带 Windows PowerShell 5.1；不再把 PowerShell 7 作为必需依赖。

同时移除模型许可证下载中的 PowerShell 7 专用参数，改用共享下载器和固定 SHA-256 校验；版本探测通过 .NET 进程 API 分别收集标准输出和错误输出，兼容 5.1。子进程使用自身的默认模块目录，避免继承 PowerShell 7 的模块路径后导致 5.1 无法加载 `Get-FileHash` 等系统命令。执行策略仅应用于子进程，不修改系统或用户配置。

已从 PATH 中移除所有 `pwsh` 命令，并确认该命令不可见后实跑 `npm run setup`：npm、.NET 工具/项目包还原、模型校验及四个媒体工具检查全部成功，实际使用系统 Windows PowerShell 5.1。六项脚本测试通过，其中下载器分别在 PowerShell 7 和 5.1 下验证缓存、回退、校验失败保护及原生程序探测；另验证无 `pwsh`、带空格的脚本路径和字面参数传递。

本次安装验证复用已校验的运行时缓存，未重复下载全部大型文件；业务代码没有修改，未重复运行上一节的 .NET / 前端业务测试。记录位于 `.artifacts/powershell-compat/setup-no-pwsh.log`、`runtime-no-pwsh.log` 和 `tests-no-pwsh.log`。
