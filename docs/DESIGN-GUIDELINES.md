# 界面与表单设计准则

Vroom 是持续工作的桌面工具。界面保持紧凑、平静、可预测，沿用 Spectrum 标准控件、设计 token、系统字体及现有页面最大宽度。保留工作区 Tab 的基本设计和状态保活机制。

## 让操作说明功能

导入和播放、修改标签、建立自动规则、组合筛选和批量处理应形成连续路径，不要求先进入配置管理，也不另设新手/专家模式。主要入口使用紧凑图标与短文字；在具体任务出现时提供下一步：筛选后保存列表、多选后批量处理、选项旁查看资料、规则旁试算。必要动作不能只藏在 tooltip。

沿用同一套字段、查询、选择范围和撤销交互。普通标注自动保存；配置草稿自动保留，点击应用生效；只有本次影响已有数据时显示变化确认。反馈优先说明实际对象、前后值、命中规则和结果位置，避免笼统成功提示或直接暴露执行器参数。

应用设置逐项即时保存，不设页面级“保存设置”。路径等自由输入在 Enter 或失焦时提交，避免半成品生效；字段内呈现保存进度和失败重试。需要耗时发布的全局设置在选择后直接打开影响确认，取消不生效，确认后展示后台进度。更新运行时路径和默认选项不得替换已经挂载的播放器或打断正在执行的任务。

不增加常驻教学段落。通过替换术语、去掉重复标题和收起非当前任务内容维持文案密度，不靠缩小字号。保留完整能力及可发现的高级入口。页面预览应对应真实配置位置，试填只改变预览状态。自解释性最终用无步骤提示的用户任务验证，构建或单元测试不能代替。

后台刷新保留当前计数、列表和操作状态，收到结果后原位更新；不能为每次数据变更隐藏计数、清空列表或反复禁用按钮。任务进度本身不触发影片查询，资料变更事件才使结果失效；连续事件合并刷新，同一查询最多一个在途读取，并保留执行期间到来的下一次刷新请求。切换查询后的旧响应不得覆盖新范围。

页面内任务反馈只呈现任务名、状态、必要的进行中进度和一份结果摘要；完成后去掉进度条和重复的完成文案。查看任务直接定位该任务详情，来源名称与结果共同成行，影响对象归入所属结果组；只有实际截断时显示结果数量限制，执行记录与诊断默认折叠。

## 层次先来自关系

界面文案使用独立 ICU 语言包，遵循 `docs/I18N.md`。给译者完整语义与具名参数，不拼接零碎文字；英文扩展后仍保持字段归属和动作对齐。界面语言偏好与标签文案的全局默认语言有明确分工；实例弹框只管理翻译，不配置全局规则。语言切换不能丢失草稿或重挂载播放器。

先确定信息属于哪个任务、哪个分组、哪个字段，再决定对齐、宽度和间距，最后调整字号、字色与字重。把所有字变小、变灰，不能修复组织关系。

一个字段是一个完整单元：**字段名 → 当前值或控件 → 说明 → 字段内操作**。说明、错误、兼容性提示、浏览按钮、添加参数等，都归入所属控件一侧。它们不能漂浮到表单左边，也不能与下一个字段产生视觉关联。

同层级的字段使用共同的标签列和控件起点；子设置放在父控件下面。先选值类型，再选兼容的录入组件，最后调整组件参数，就是这种顺序。修改权限和查询能力属于另外的逻辑组，不与组件参数混排。

标签配置按“基本信息 / 编辑 / 展示 / 查询 / 自动解析与更新”组织。编辑组件、修改权限和编辑位置归入编辑；展示组件和展示位置归入展示；筛选、排序、查重、分组和分类入口归入查询。位置是用途的子设置，不再形成独立的任务页。表单模式不放独立预览侧栏；编辑、展示、查询各在底部提供对应的试填、展示和条件匹配预览，试填不写入真实标注。结构和 JSON 模式保留页面预览侧栏。自动配置依次区分条件填写、导入解析、外部补全和后续更新；重复项先显示可比较的摘要，完整参数进入单项编辑弹窗，取消不写入外层草稿。

**先确定配置的作用域，再决定控件放在哪里。** 应用级的单例设置只在全局设置中配置；项目、字段、文案等实例编辑器只显示与当前任务有关的状态，不能再提供一套独立开关。不能为了操作方便，把全局默认值复制成每个实例各自可修改的偏好。修改全局设置后，各入口必须读取同一个有效配置。

分组依据用户的决策，例如“文件与位置 / 扫描行为”“列表内容 / 结果排列”“文件命名 / 队列调度”。不要依据实现模块、控件类型或凑齐列数分组。短表单不必增加分组标题，切换栏已经说明的标题也不重复展示。

## 文字分工

界面字体统一来自 `--app-font-sans`：优先使用平台 UI 字体名（Apple 系统字体、Segoe UI），再交给通用无衬线回退。不要把受界面语言影响的 `system-ui` 放在最前：本机中文 Windows 的实际对照中，它将中英文都选成雅黑，使英文和数字明显变宽。Spectrum 的 sans 字体变量与中文本地化规则也须接入同一字体栈，覆盖页面、控件和 portal 浮层；不能仅修改根元素后假定控件已继承。代码与路径保留等宽字体。变更字体时同时检查中英文、输入控件、浮层及代码编辑器的实际渲染。

以下是 Spectrum 当前桌面密度下的参考值；代码引用 token，不能另建颜色或字号体系。

| 角色 | 字号 token | 字色 token | 字重 |
| --- | --- | --- | --- |
| 页面标题 | `--s2-font-label`，约 16px | `--s2-content-heading` | 500 |
| 分组标题 | `--s2-font-body`，约 14px | `--s2-content-neutral` | 500 |
| 输入值、选项、勾选项文案 | `--s2-font-body`，约 14px | `--s2-content-neutral` | 400 |
| 字段名 | `--s2-font-detail`，约 12px | `--s2-content-subdued` | 400 |
| 提示、单位、来源与说明 | `--s2-font-detail`，约 12px | `--s2-content-detail` | 400 |
| 次要计数、技术标识 | `--s2-font-micro`，约 11px | `--s2-content-detail` | 400 |

大胆使用小字号和弱字色表达辅助信息，但不弱化输入值、错误、冲突、焦点和当前选择。错误保留语义色和明确文案。不要以粗体替代分组，也不要用透明度统一降低整个表单的对比度。Spectrum 控件内部的字号、交互状态和焦点样式遵循组件标准。

字段应有持久可见的名称。占位提示会在输入后消失，选中值也不能代替字段名。搜索框和已经由上下文唯一说明的工具栏操作可以保持紧凑，但仍须有可访问名称。标签应简短，单位、示例和长条件放到帮助文字中。

## 对齐、宽度与留白

- 常规设置使用标签在左、控件在右的行布局。共享标签列为 100px，列间距为 Spectrum 16；标签与首个控件对齐，不与整段帮助文字垂直居中。
- 单个设置表单最大宽度为 676px，控件列最多 560px。数值通常最多 160px，选择器和日期通常最多 360px；路径、长文本和多语言内容可以占满控件列。数据密集的编辑工作区仍使用现有页面容器，不把所有字段强行拉到整页宽。
- 字段内部用 Spectrum 4 / 8 间距，字段之间用 16，逻辑分组之间用 24 左右。先建立“近者同属、远者分组”，不要给每一行相同的大空隙。
- 常规表单可用宽度低于 420px 时，行布局变成上下排列。密集属性编辑统一使用 `FormLayout compact`，保持 100px 标签列，低于 320px 才堆叠。根据容器宽度响应，不能只看窗口宽度；分栏、侧栏和弹窗可能更窄。不要为单个页面另设一套阈值。
- 并排字段应有共同语境，例如开始/结束、同组编码参数。普通设置不用自动填满页面的多列网格。组内长文案允许换行，按钮不挤压输入值。

## 控件和操作的归属

开关或勾选项的文案紧邻控件，不把开关推到页面远端。多个独立权限通常纵向排列；“筛选 / 排序 / 查重”一类简短并列能力可同行。条件开启后的设置放在该控件下面，保持依赖关系可见。

“浏览目录”“添加参数”“复制规则”等局部动作属于字段；放在控件旁或其下方，使用安静的小按钮。保存、预览、执行属于表单或任务，集中在底部操作区。按钮宽度由内容决定，避免普通保存操作变成横贯面板的大色块。

克制不等于消除操作特征。没有紧邻图标或上下文时，裸文字按钮容易被看成说明或标题，应使用标准次要按钮、动作图标和明确的动词。“选择已有项”和“新建并使用”是两条替代路径：选择器要标明当前选的是什么，新建按钮要说明它会创建并切换，不能只写一个看起来像静态标题的名词。

规则首先呈现“读取属性 / 判断方式 / 比较值 → 匹配后填入”，数值和单位相邻。组合计算通过明确入口展开，用读取内容、比较值、上下限、条件和结果等语义名称标识操作数，不用参数编号代替含义。

嵌套对象和计算表达式使用短标题、缩进和必要的引导线表达深度。条件规则和影片查询共用 `ConditionGroup`、`ConditionBranch`、`ConditionRow`，以完整组容器表达包含关系，保留各自的数据合同。每个参数仍有自己的名称、控件和操作。重复行的移除动作留在该行，不与整组操作混淆。

表单模式的编辑、展示、查询预览固定在编辑区下方，主表单与底栏分别滚动。底栏可收起并保留试填值。编辑试用直接呈现实际控件，禁止手动修改时禁用控件并说明原因；展示预览明确排列“示例值 → 显示结果”，示例输入不藏在折叠项中。已配置位置提供“查看页面位置”打开实际布局，无位置时不显示无效选择器；多个位置才提供选择。查询结果用文字、图标与 Spectrum 语义颜色同时区分匹配、不匹配和未知。试填不写入标注或配置历史。值类型仅在基本信息配置，不在编辑页重复。

**同一属性表单只建立一套列。** 组件选择器、普通参数、对象子字段共用标签列、控件列和末端操作列。对象组使用 `FormGroup`，只缩进子字段的标签；控件起点不随深度改变。不得把另一张完整属性表单塞入一个字段的控件列，否则每层都会再增加标签宽度，形成阶梯状排列。输入组件和展示组件必须使用同一个 `ComponentSettings`。

参数顺序由公共 schema 的声明顺序确定，普通字段在前、对象组在后，未注册的已有参数继续保留。用户添加参数的先后顺序不应改变最终排版。移除字段和移除整个对象分别放入对应行或组标题的末端操作位，使用 `FormRemoveAction` 提供统一图标、具体可访问名称和提示。

折叠入口不自动成为分组标题。“文本约束”这类字段的附加设置放在所属控件下方，使用 12px subdued 字色、常规字重和展开箭头；展开内容留在同一控件列内，不能顶格占据独立分组的位置。折叠时不保留给展开内容预留的大空白。独立任务组才使用分组标题；已有切换栏说明当前任务时，去掉重复概括标题。

输入值可以与分组标题同为 14px，但角色必须由位置、控件背景、字重与间距共同说明。不要要求用户仅凭字号猜测一段文字是标题、值还是展开操作。

多语言字段必须是可直接录入的标准文本框，编辑全局默认文案语言；只有右侧“多语言”按钮打开翻译编辑器。界面语言和默认文案语言统一收在“设置 → 语言”，两者用途不同。翻译弹框采用“默认文案 / 其他语言”结构，默认语言只读展示，不提供实例级配置；共用 `FormLayout` / `FormField`，各语言可直接对照编辑。不要重复展示当前正在编辑的文案作为“默认参考”，也不要为两种语言固定一整块空工作区。少量语言直接显示，多语言集合才提供搜索和未填筛选，长集合按最大高度滚动。取消只撤回弹框内改动，不能撤回打开前已录入的值。

共享文案引用仍须保留引用和参数语义，明确转为独立文案后才直接编辑。全局语言切换不应覆盖或删除已有翻译；缺少全局语言的录入框显示为空，不能拿回退显示值冒充可编辑原值。

列表、规则等复合编辑器先划分工具栏、内容区和新增入口，不能把数量、空状态、字段名、保存方式、共享说明、来源选择各排成一行。主区域保留高频编辑任务；数量和状态并入工具栏，低频配置放到明确命名的设置弹层，详细说明放到共享信息 popover。空列表不重复展示“0 项”“暂无内容”“添加第一个”三份同义信息。

可操作的选项须有列表结构。优先使用 Spectrum ListView 等标准集合组件，保留行边界、图标、焦点和行内操作；不能仅凭分散的文字与右侧按钮暗示一行。不要用勾选或选中背景伪装编辑行为，行点击若可用，应明确对应打开编辑。辅助设置面板的开关状态不应改变主编辑区的基本结构。

**重复数据先给可比较的概览，再提供单项编辑。** 多个项目具有相同字段时，用列标题一次说明字段含义，每项以一行摘要呈现名称和关键值；不要把每项都展开成一张大表单，重复标签、说明和嵌套边线。完整字段放入明确命名的单项编辑弹窗，沿用公共属性表单。范围、代表值、别名等不同语义须有各自名称，不依赖位置或颜色让用户猜测。

集合名称、数量与集合动作属于工具栏，单项编辑与移除属于对应行；整组移除放在组设置中，并明确写出作用范围。窄容器把一行转换为带字段名的紧凑摘要，保持项目边界、操作位置和可访问列名；不能退化为无标签的文字堆。概览只保留必要的行分隔，不再增加外框和每项卡片。编辑中的临时值在“应用到草稿”前不写入外层草稿，取消应保留原值；仅允许修改部分属性的入口，不能顺带开放其他字段的编辑。

## 边界保持克制

优先使用留白、对齐和轻微底色区别区域。保留工作区分栏、必要分组分隔、输入边界和焦点指示；不为每个字段、面板和嵌套层反复套边框。分隔线使用 `--surface-border`（Spectrum subtle），圆角和阴影使用共享 Spectrum token。

有外框的列表，末项分隔线不能再重复充当底边。验收时检查首尾项与容器边界，尤其留意内容高度与容器高度不一致时出现的双线；虚拟列表按当前集合的末项处理，不能把最后一个已渲染节点误当作最后一项。

短列表按内容自然高度收紧，只为长列表设置最大高度并启用纵向滚动。不能用“条目数 × 估算行高”填充容器，也不能只隐藏末项分隔线而保留下面的空白。单项、说明行、搜索无结果以及筛选后由多项变为单项，都须检查末项与内侧底边的贴合程度。

帮助文案属于普通说明时，不使用大型提示框。只有需要用户注意的状态、错误、风险或执行结果才使用语义提示组件。

## 代码中的共同实现

优先复用 [`FormLayout.tsx`](../src/Vroom.Client/src/components/FormLayout.tsx)：

- `FormLayout`：设置表单的宽度、字段间距及容器响应；`compact` 用于密集属性编辑。
- `FormSection`：按任务语义组织的分组，标题与可选说明。
- `FormGroup`：属性表单中的对象组，标题与整组操作共同表达作用范围，子字段继续使用外层控件列。
- `FormField`：标签、控件、说明和局部操作；`layout="row"` 用于常规设置，`trailingActions` 提供统一末端操作位，`depth` 只影响标签缩进。
- `FormRemoveAction`：带具体作用对象名称的标准移除按钮。
- `form-actions`：整个表单的操作行；控件内操作使用 `FormField.actions`。

注册组件的录入与展示设置统一经过 `DesignerFields.tsx` 的 `ComponentSettings` / `ParameterFields`。页面只提供组件选择器、说明和数据回调；不再自建参数标签列、父组容器、移除按钮或字段顺序。

图标参数统一使用可搜索的 `IconPicker`，候选项和当前值都显示实际图形，目录与 `SchemaIcon` 渲染及公开能力注册保持一致。多语言入口使用 Translate 图标。集合标题已有分隔线时，不再添加相邻容器的第二条顶边线。

规则配置按“何时执行、要做什么、填入什么、如何处理已有内容”组织，并用当前选择生成一条结果摘要。写入策略用结果表述，来源优先级以可调序的具名列表编辑，不要求输入内部来源 ID。分类与文本处理规则提供就地新建、编辑入口，不能只给一个无去向的选择器；共享资源编辑明确影响范围。嵌套弹窗的修改留在父弹窗，取消父弹窗全部丢弃，应用时相关资源进入同一个可撤销的草稿事务。

规则运行条件复用查询的“属性—判断—比较值”与条件组容器。默认不限制条件；启用后必须选择属性，不能用一个默认布尔值代替可理解的条件。事件字段随触发时机提供，未完成或无法返回布尔结果的条件不能应用。复杂表达式留在次级入口，开启编辑不能重写已有含义。保护说明在整项规则的最后；字段值、静态动作与来源优先级共用表单正文 token，不从弹窗继承较大字号。

展示样式使用本地化名称并列出实际使用位置，不向用户显示 profile 的内部 key。名称编辑不改变位置引用。展示组件、名称和使用位置共同表达一套样式的作用；新增样式与选择展示位置使用同一名称。

可比较的重复数据复用 [`CollectionEditor.tsx`](../src/Vroom.Client/src/components/CollectionEditor.tsx)，集中管理集合工具栏、语义表格、空状态、行操作与窄容器摘要。业务编辑器只提供列定义、数据和编辑回调。数值分档配置与路径规则中的别名编辑共用 `FacetBandsEditor`；单项弹窗继续使用 `FormLayout` / `FormField`。仅需名称和状态的选项集合继续使用 Spectrum ListView，不为统一外观丢失标准集合交互。

```tsx
<FormLayout>
  <FormField layout="row" label={name} description={help} actions={localActions}>
    <Input aria-label={name} value={value} onChange={setValue} />
  </FormField>
  <Space className="form-actions" wrap>{saveAction}</Space>
</FormLayout>
```

`FormField` 为复合字段提供组名称与帮助关联；内部控件仍必须提供与可见名称一致的 `aria-label`，或使用 Spectrum 自带的 `label` 关联。不要把含多个交互元素的复合控件包在原生 `<label>` 中，不要通过宽泛的 `label` 选择器重写 Spectrum 内部布局。

schema 表单、字段信息 popover、结构属性表与实时标注沿用各自的共享渲染器，并遵循相同层次。布局尺寸是通用组件行为，可由公共 schema 提示调整；不能根据具体业务标签 key、名称或值决定样式。公开资源提供的文案继续使用共享本地化合同。

## 修改后的验收

操作密集的页面使用共享 `Ribbon` / `RibbonLayout`：任务标签、命令分组、顺序和文案来自公开布局资源，页面只提供已注册命令与控件。标题与数量后紧邻任务导航；导航使用 React Aria 的 Tab 语义和键盘行为，以 Spectrum token 构成独立的分段区域，选中项有明确底色、轮廓和焦点状态。上下保留 Spectrum 12 留白，标题过长时省略，窄容器把导航移到下一行，不让标题挤掉工具标签。下方是一个完整的中性工具面板。组名在控件上方，共用标签行和操作基线；默认使用 Spectrum M 尺寸、具备点击边界的操作按钮，切换操作使用 ToggleButton 显示选中状态。搜索框保留较大宽度，低频的连续参数进入具名弹层并显示标签和当前值，避免把滑块和不同高度的控件拼在一排。按容器和命令组的实际宽度，从末端逐组收为具名 Spectrum Popover；当组名也无法排下时，统一进入按原组排列的“全部操作”弹层，不增加多排工具栏或根据语言选择断点。收起只隐藏命令面板，标题、数量和任务标签保留；提供明确按钮和工具区内的 Ctrl+F1。标签/折叠状态按工作区 tab 保存。内容编辑器、批量预览弹窗和播放器不放在工具标签面板内，避免切换命令时丢失状态。

所有页面 Ribbon 通过共享 `PageToolbar` 自动进入最近的 `Page` 固定工具区，列表和影片详情不再各自实现固定逻辑。工具区与内容滚动视口作为兄弟区域排列，保持相同的最大宽度、页边距和滚动条预留；没有 Ribbon 的页面自动隐藏空工具区。配置预览隔离自己的工具栏上下文，不得把示例命令放进编辑器的页面工具区。移动命令的 DOM 位置时仍须保留声明中的可见和上级禁用条件，不移动或重新挂载表单与播放器。

Ribbon 标签使用 24px 紧凑高度，外层只留 Spectrum 2 内边距；展开和收起都使用上下各 Spectrum 12 的页面留白。收起后同时去掉标题与命令面板之间的间距，不能把这份间距留在底部。内容从工具区下方开始裁切，不用透明的 sticky 间隙或局部遮罩遮盖海报。滚动 ref、滚动位置保存、分页观察和卡片焦点仍属于原内容视口。验收应实际滚动至卡片或标题被裁切的位置，并检查折叠工具栏后及窄窗口下的边界。

影碟 3D 以盒体本身为视觉主体，不再包裹有底色、描边的矩形卡框。完整展示区只容纳盒体和柔和落影，薄边、封套反光与轻微俯视用于表现实物厚度，不添加整面悬停遮罩。盒体下方依次是片名、基础信息、完整宽度的声明字段区、独立操作行；资料不能与按钮共用左右两列而被挤窄，所有原卡片 Slot 的值都必须保留。操作行用一条弱分隔线区分字段显示与字段操作，常驻显示字段操作、播放、详情。操作统一使用 Spectrum S 尺寸的无边框图标按钮，提供可访问名称；播放和详情保留提示。纯图标按钮不渲染文字节点，不能用 CSS 隐藏文字后继续保留组件内部的文字列。声明字段操作通过通用 Slot 尺寸参数与同一操作行对齐，不根据字段 key 调整尺寸。验收应实际核对按钮、图标尺寸和水平/垂直中心。不能用点击封面或片名代替明确的详情按钮。悬停影碟或键盘聚焦封面时翻转；访问文字和按钮时不触发翻转。展示区按可用宽高约束盒体尺寸，小卡片也应保持足够占比；不能重复扣除几何边距和控件空间。验收必须包含字段齐全、长标题、最小卡片以及与非 3D 模式的内容对照，不能只验证空字段样例。

3D 与非 3D 卡片共用标题、资料和操作区布局。标题统一从等高的封面展示区下方留 Spectrum 8 间距，不能根据展示模式覆盖标题间距。常规比例的 3D 盒体高度占展示区约 92%，宽封套仍受旋转宽度限制；展示舞台仅保留随尺寸缩放的透视余量，不叠加固定上下内边距。验收须将两种模式并排，在不同海报尺寸下核对标题起点，并检查翻转过程中的盒体边界，而不只比较字段内容。

高频筛选使用“编辑草稿 → 应用”的完整事务式交互。条件、搜索、排序和分组在面板展开期间只改变草稿；统一的应用按钮提交一次，取消恢复已生效配置，重置只改草稿。收起与切换标签保留草稿，不能在选择字段、输入半个数值或增加条件时查询。未完成条件应显示具体提示并阻止应用。已生效的条件数留在筛选入口，保存智能列表使用已应用的查询。

条件行按“字段 / 比较方式 / 比较值 / 移除”排列并提供可见名称，字段可搜索；新增时让用户选择字段，不替用户猜一个业务字段。常用操作直接呈现，嵌套条件、排除和时间范围按需展开。排序和分组为可增删、可调序的字段集合，排序明确优先级、方向与空值位置，分组说明组合统计语义。方向按钮必须用图形和可访问名称同时表达当前方向。重置与取消、应用共用末端操作栏，不再散落一个无归属的“清除筛选”。

查询同时管理条件、排序和分组，入口统一命名“查询”，不再称为“筛选”。表单与 SQL 是同一查询草稿的两种编辑视图，切换不执行查询，不另存第二份生效配置。语法或类型错误留在草稿中并阻止转换、应用；不能用上一次合法值冒充当前输入。SQL 的字段补全同时提供稳定标识和本地化名称，操作范围与当前影片库上下文保持一致。

**嵌套条件必须能看出完整的包含关系。** 每个条件组用共享容器表达组标题、匹配方式、内部条件和组内添加入口，组移除只在组标题。直接子项之间显示“并且 / 或者”，不能让连接词跨越组边界；子组有完整、克制的轮廓与内边距，不能仅靠一条淡竖线或微小缩进暗示嵌套。组的添加操作留在自己的底部，不能与父组动作挤在一块。空 AND/OR 组的匹配结果必须明确说明。

**组背景覆盖整个包含范围，单条条件始终使用同一中性底色。** `ConditionGroup` 根据实际容器嵌套使用相邻的中性层级与低饱和色相，查询和规则编辑共用同一深度上下文；时间范围、排除及引用关联也占一个容器层级。颜色只帮助追踪层级，不表达真假、错误或业务类别。子组保留完整轮廓、内边距和一条窄的左侧层级标记，根组融入工作区。同层组使用同一底色，条件行不能随深度黑白反转。

**对比度要服务于角色，不能把每一层都做成抢眼的色块。** 组头是紧凑的标题、匹配方式和组操作，与组背景连成整体，不铺横贯全宽的亮灰标题条。组使用 Spectrum `gray-75` / `gray-100`，条件行统一使用 `base`；色相仅少量混入组背景，稍明显的色彩限于窄层级标记。输入值、标题和错误保持正常对比度，字段名使用小字号弱字色。连接词只占相邻项之间的短行，不再画横贯工作区的分隔线。不能仅调高背景亮度就宣称层次改善；必须同时检查容器范围、控件辨识、操作归属和整屏视觉重量。规则的“匹配后填入”放在独立中性结果区，与条件树分开。保留标准 token，不硬编码 RGB，不增加逐层粗框或逐条条件边框。

编辑中的排序/分组项使用共同的浅底色与内边距，将编号、字段、方向或分组方式、调序/移除及附加设置包成一个整体。展开的设置仍在该项底色内。不要为了减少边线，把编辑项退化成漂浮控件。验收至少包含混合 AND/OR、排除、二层以上嵌套、多个排序项及一项展开附加设置；仅检查简单单条件不能证明层级合格。

编号与行内操作对齐到输入控件的垂直中心，标签单独占行；用共享网格行建立关系，不用固定上边距补偿。窄窗口换行和附加设置展开后，这个对齐基准不变。“更多条件”是操作集合，使用标准菜单，入口与其他添加按钮同高；菜单弹出不改变组内操作栏高度，不把展开内容塞进横向按钮行。

智能列表保存完整的已应用查询，包含嵌套条件、范围、搜索、影片库约束及全部排序/分组字段。显式清空集合也是有效选择，重新打开时不能按“为空”补回默认字段。分页位置属于浏览状态，重新打开从第一页开始；未应用草稿不能混入已保存列表。

检查普通设置、密集参数、弹窗、侧栏和嵌套表单，覆盖桌面宽度和窄容器。除空状态外，还要看已填长值、展开子设置和错误状态：

1. 不读帮助时，能否识别每个控件的含义？
2. 每段说明、每个按钮能否明确找到自己的所属字段？
3. 同层字段是否对齐，子项是否紧随父项？
4. 输入值是否比字段名清晰，字段名是否比说明清晰？
5. 窗口缩窄后是否保持逻辑顺序，且没有横向溢出或过早堆叠？
6. 焦点、键盘访问、验证、草稿、预览和保存行为是否保留？
7. 同一属性表单中，选择器、普通参数与子组参数的控件起点是否一致，末端操作是否同列？
8. 单项列表是否贴合内容，最后一项下面是否还有额外线条、空白或无意义的滚动条？
9. 重复项目能否直接比较，集合动作和单项动作是否有明确归属？窄容器的摘要是否仍有字段名称？
10. 单项编辑的取消、应用到草稿、单项移除和整组移除是否保持各自的作用范围？

代码审查不能只看新增 CSS。需要实际渲染、查看截图，并记录验证范围；未进行的原生或移动端验收不能描述为完成。

验收前列出可定位的页面与状态清单，分别记录“源码已审查”和“已在界面验证”。折叠、展开、条件开启、已有值、空值、错误、长文案和窄容器不能互相替代。自定义折叠容器显式使用 `form-disclosure`（附加设置/诊断）或 `disclosure-section`（独立内容分组），不再用全局 `summary` 字号代替角色判断；Spectrum 折叠组件保留组件标准。

功能测试和构建只能支持功能、类型与打包结论，不能证明视觉层次清楚。做了代表性页面检查时，报告代表性检查及未覆盖项，不能写成“全局全部验收通过”。移动字段说明时，同时核对可见归属与可访问描述关联。

消息中心作为工作区右侧的独立滚动区域，展开/收起不移动页面内容的组件所有权。默认显示整个资料库的动态，明确标示范围与最新在前；待处理与阅读状态分开。任务块复用共享任务摘要和详情入口，建议块保留对象、字段信息、建议值与显式对比操作。窄容器使用右侧浮层，避免把主编辑区压到不可用；焦点与可访问按钮保留。折叠状态和筛选按工作区 tab 保存，播放器不因侧栏配置改变而重挂载。
