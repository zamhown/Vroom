# 当前标签协议与架构审查

更新：2026-11-03。以下描述当前实现；历史迁移文档不作为当前合同或兼容要求。

## 数据边界

字段声明、值集合、值实体和标注是不同概念。声明描述合同，不是可标注实体；影片及其时间范围、可枚举值实体才是标注主体。例如，主演字段引用一个人物 Term，该 Term 再通过出生日期、性别等字段获得资料。

| 对象 | 职责 |
| --- | --- |
| Definition | 值类型、对象、组件、位置、初始化、补全与查询权限 |
| Vocabulary | 值实体的成员集合；多个字段可以共用 |
| Term | 稳定 ID、名称、描述、别名、成员资格及修订 |
| Annotation | 主体、范围、字段和值，以及来源、版本和历史 |
| Projection | 当前合同允许的有效值、诊断、引用和查询索引 |

声明 `parents` 是配置 DAG；有效 Term → Term 引用是另一个跨字段 DAG。所有写入口在同一事务结束时检查完整实体关系图。数字和文本不强制实体化，同名不合并身份。可枚举值只有 `{term: id}` 一种编码。

四个独立标注对象仍为：影片、标签值、影片时间点、影片区间。只有格式 3，没有旧字段转换、旧数据库升级或旧样例兼容。

## 审查建议的落实

### 共享能力合同

`host-capabilities.json` 统一登记组件的角色、类型、基数和参数 schema，执行器参数、事实路径、表达式、来源协议及功能要求。`editor-dependencies.json` 只描述交互依赖，不重复定义组件能力。主 schema 引用能力 schema；服务端、Monaco 和内置 Agent 读取同一套离线资源。

发布前校验未知参数、组件与值类型、集合限制、规则目标、媒体属性类型、来源及属性引用、查询能力和功能要求。前端联动不代替服务端验证。错误包含诊断码与 JSON Pointer。日期是 ISO 日期字符串，`date@1` 使用日历控件并验证真实日历日期。

### 独立 Query AST

`query.schema.json`、`QueryContract` 和查询编译器共同定义条件。支持布尔组合、类型检查、缺失、成员、集合、同一关联实体条件，以及时间范围的 any/all/none 量词。时间区间采用整数微秒、左闭右开语义；all 要求至少一个匹配范围。

排序明确区分值、引用名称、集合 min/max 与空值位置；分组支持完整值、集合成员展开和配置分类。列表、视图、播放列表来源和批量目标使用同一查询入口及权限检查。名称搜索改用引用索引关联，不再截断名称候选或展开大量 OR。

### 增量投影和快照读取

名称、说明和布局变更不重投影标注。值合同、集合成员或值启停发生变化时，只处理受影响字段、主体和原始引用；保留原始引用索引，以便恢复此前失效的标注。逐条读取和投影避免把全部 JSON 历史装入内存。当前页标注批量读取。

配置编译快照按原始配置与值修订戳缓存。写事务统一更新有效值、诊断、引用、时间范围索引和完整 DAG；WAL 只读连接在事务期间仍读取上一份完整已提交状态。这里采用 SQLite 事务原子切换，没有另建第二套影子数据库。首次初始化和整包导入仍可全量重投影。

发布任务报告已处理数量。提交前停止会回滚整个事务；进入原子提交后不再中止。重试复用预览令牌，重新处理未提交事务。任务元数据持久化；事务内进度为实时内存计数，不能冒充逐条持久化检查点。批量标注保留原有逐对象恢复逻辑。

### 领域对象与展示边界

配置编译只接受 `DefinitionDocument`，拒绝带客户端 `terms` 投影的文档。来源任务使用类型化 `SourceSnapshot`，网络请求在事务外执行；写入时重新取得当前有效合同，并检查世代与修订。

查询合同/编译、能力合同、投影已分离职责。数据库事务仍由同一个 TagEngine 单元管理，避免拆成互不一致的服务。完整 ClientSnapshot/AnnotationCommand 类型化尚有继续收紧空间，不宣称所有 JsonObject 边界已消除。

### 面向任务的配置表单

标签管理提供“表单 / 结构 / JSON”，共享保留的完整草稿。基本信息先确定值类型；`value.schema` 和 `value.cardinality` 是唯一依据，公共能力注册表登记类型模板、推荐组件、图标和组件的值合同要求。切换录入组件只改变展示，不反向修改数据类型；改变类型保留其他策略，由发布校验报告不兼容项。枚举集合变化同步它的字典匹配规则。

表单与结构模式复用同一个紧凑多语言入口，弹窗采用可搜索语言列表、未填写筛选、完成状态和单语言编辑区，保留导入语言及文案引用。配置修改/查询权限使用 checkbox。编辑器与独立滚动的预览区并列，窄窗口堆叠；预览试填不写标注。

自动填入表单覆盖常量、媒体事实、字典匹配、分档别名、正则捕获处理及表达式，事件和条件可直接编辑。表达式复用可执行 AST；事件事实按触发事件限定，来源请求不能读取事件载荷。来源字段的多语言名称与解析路径分离，格式对应的提取、数量、规范化和链接处理可编辑。新集合、来源覆盖与引用它的字段作为同一变更集预览/发布。显示位置合并宿主槽位和当前布局声明区域，并联动可编辑/展示/导航模式。

全局布局树、完整来源请求与扩展包仍可由结构/JSON 编辑；标签自身初始化和事件策略均可在表单中编辑。

## 干净的系统标签

内置包版本 3.4.0，格式 3。共 38 个字段、6 个分组、8 个集合（以资源文件为准）；没有验收用字段或人物样例。

- 删除年龄，保留出生日期。年龄随时间变化，不持久化重复事实；以后需要时可通过显式的派生展示计算，不回写一个固定年龄。
- 删除独立“资料来源”字段。每条标注自身已保存来源、时间和规则版本，统一在字段说明中展示。
- 新增发行日期、导演、系列、语言、笔记。主演与导演共用人物集合，因此同一个人物的资料不重复。
- 出生日期和性别只标注人物值实体。主演和通用标签可用于时间点/区间；笔记可记录整片或片段。厂牌等整片信息不再默认开放时间范围。
- 未获得评价时保持未设置，不再填入一个伪默认评分。长文本、图片和路径等不开放没有明确意义的排序/查重；配置仍可覆盖这些能力。
- NFO 来源补充发行日期、导演、系列、语言和厂牌映射。内置文案与说明均有中英文；具体 key 只存在于默认资源和测试。

完整清单见 [SYSTEM-TAGS.md](SYSTEM-TAGS.md)。系统文件与用户覆盖仍分开更新。新样例使用独立数据目录，旧样例、媒体和其他目录不会被删除或迁移。

## 规模验证

本机合成目录测试，20 次热查询样本；数据生成不计时。1 万和 10 万影片分别含约 3 万/30 万条标注、1000/10000 个值实体。配置合同变更包含预览与正式发布两轮投影，改变字段上全部有效标注；名称改动不重投影。

| 规模 | 列表 p95 | 筛选 p95 | 名称搜索 p95 | 值改名 p95 | 文案发布 p95 | 合同变更（单次） | 进程峰值 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 10,001 影片 | 42 ms | 44 ms | 106 ms | 54 ms | 127 ms | 0.92 s | 154 MiB |
| 100,001 影片 | 269 ms | 325 ms | 806 ms | 196 ms | 310 ms | 8.09 s | 360 MiB |

测试入口：`tools/Vroom.Smoke/TagBenchmark.cs`，`--tag-benchmark`。结果写入 `.artifacts/tag-benchmark-results.json`。峰值是整个基准进程峰值，并非单请求分配量；不是冷启动、NAS 扫描或百万规模保证。流式处理前同规模进程峰值约 925 MiB，改动后约 360 MiB；两轮系统负载不同，不以此推算查询速度提升倍数。

## 仍值得继续优化的地方

1. 10 万规模名称搜索 p95 仍约 0.8 s，下一步应以查询计划决定 FTS/规范化名称索引、数值索引和深分页优化，避免无依据地增加索引。大型导入与极大 Term 图的内存/图校验另做基准。
2. 继续为来源、导入及客户端快照收紧类型边界；为布局动作等扩展参数逐项增加可执行能力合同。公共 registry 不能只做静态说明。
3. 发布预览目前在写入队列上做可回滚计算；很大变更仍会阻挡其他写请求。可考虑独立候选投影世代，但必须同时验证恢复、磁盘放大与并发世代冲突。
4. 标签规则表单已覆盖注册执行器与表达式；后续可为全局页面布局和完整网络来源请求提供专门的任务编辑器，继续复用现有 schema，不增加第二套 DSL。
5. 本次原生验收以 Windows 构建为界。移动设备日历、长列表、触摸拖拽和 NAS 波动仍需实机验证。

具体测试与宿主记录见 [VALIDATION.md](VALIDATION.md)。
